# GeoAI AI效果实测报告

评测日期：2026-11-11。对象：本地Streamlit完整项目的知识问答RAG及海淀区参数解析；不是GitHub Pages合成体验版。

## 知识问答：主要结果

| 指标 | 结果 | 分母和解释 |
|---|---|---|
| Recall@3（逐题平均） | **96.88%** | 16道可回答题；15题为100%，QGIS题为50% |
| Precision@3（逐题平均） | **35.42%** | 17个标准充分证据片段命中 / 48个检索位置 |
| Hit@3 | **100%（16/16）** | 每题至少找到一份充分证据；不等于召回所有相关片段 |
| 回答级无依据扩展率（幻觉代理指标） | **5.00%（1/20）** | AI逐条核对，未经独立人工复核；不是外部事实错误率 |
| 资料不足/越界题正确拒答 | **100%（4/4）** | 未编造建筑总数、沉降标准数值、实测高度或密钥 |
| 知识问答真实API调用成功 | **20/20** | 调用成功不代表答案完全正确 |

**不能把5%写成已客观验证的事实幻觉率。** 本轮没有对所有事实进行外部权威核验，也没有独立人工标注。严格的事实幻觉率暂记未测。这里的5%只表示至少出现一条无检索依据领域扩展的回答比例。1/20的Wilson 95%区间约为0.9%–23.6%，小样本不支持稳定性承诺。

## 口径与标注

知识库为现有3份Markdown、13个索引片段；不重建索引、不修改提示词或产品检索逻辑。标准答案在运行前冻结：16道可回答题、4道无答案/越界题。单个片段只有能独立充分回答问题时才标为标准证据；部分支持、背景相关不算本轮命中。QGIS特点在两个重叠块中都能完整回答，所以两块都标为标准。标准由开发者编写，未经独立相关性标注，题目较贴近知识库，不能代表真实用户总体。

Recall@3 = 每题检索到的标准片段数 / 该题所有标准片段数，再对16题平均。Precision@3 = 每题检索到的标准片段数 / 实际返回片段数，再平均。无答案题不进入两项检索指标分母，其拒答单独评估。

**精确率存在标注上限：**16题中14题只有1个标准片段，另2题各有2个，但系统固定返回3个。按这套“独立充分证据”的窄口径，理论最高Precision@3只有18/48=37.50%。本轮17/48=35.42%接近该上限；不能据此称“只有35%的检索内容正确”。按全部标准片段微平均召回为17/18=94.44%，也不能与逐题平均96.88%混用。若要评价噪声，应另标“部分支持/背景相关/无关”，而不是事后改标签提高结果。

4道无答案题仍各返回3个片段，因为系统没有检索拒绝阈值；模型回答阶段均明确表示资料不足。这不等于检索模块能识别无答案。

## 逐条发现

- R14：回答将“不良地质区域”扩展为“滑坡、崩塌”等示例；返回的片段未明确列出这些内容，也未标为外部补充，因此计入无依据扩展。该知识可能正确，仍不能说是本次检索材料提供的事实。
- R09：InSAR英文展开出现“Aaperture”拼写，应为“Aperture”。此项另计文字质量问题，未当作新增事实型幻觉；说明低无依据扩展率不代表回答无错误。
- QGIS题只命中了两份标准证据中的一份，故Recall@3为50%，但该片段已能回答问题。其余15道可回答题标准证据召回完整。
- U01/U02提出了外部查找建议。这些建议没有作为统计数值或有效标准答案给出，不按目标事实幻觉计数；建议自身未做外部核验。边界性推论和建议仍需独立人工复核。

核对细节见grounding_review.json，所有原始回答、检索上下文、ID和分数见answers.json。不得删除上述失败项或将AI评审写成人工专家评审。

## 海淀区空间指令补充评测

固定10条开发指令：6条有效（含约定句式与改写）、4条不支持或异常。同一批输入分别运行本地规则与真实DeepSeek，不计算GIS几何或修改正式任务记录。

| 模式 | 有效任务道路/距离全对 | 异常正确拒绝 | 总体 |
|---|---|---|---|
| 本地规则 | 4/6 | 4/4 | **8/10** |
| DeepSeek解析链路 | 6/6 | 4/4 | **10/10** |

本地规则失败保留P03、P04两条改写。模型结果经过产品前后校验，故该指标是应用链路表现，不是基础模型通用准确率。不将10/10写成真实用户100%成功率。

参数评测初版计分器错误地在整段错误文本中搜索“连接”等字样，未知道路错误附带的长道路列表也能包含这些字，导致一次误计。已按明确DeepSeek错误前缀修正评分，不重跑模型、不改变问题与答案；初版记录保留在parsing_results_initial_scoring.json。修正结果及原因公开，避免混入产品指标。

## 实现、调用与可复核文件

评测直接提取并执行app.py中的load_knowledge_base、search_knowledge、generate_answer函数体；仅去掉Streamlit缓存装饰器以在独立进程运行。保持归一化BGE嵌入、FAISS、Top3、deepseek-chat、temperature=0.2、max_tokens=1200。传输超时35秒、重试0、并发2；嵌入模型使用本地缓存。未改变线上产品或按评测结果调提示词。

RAG这20次API返回的用量合计：输入13638 token、输出2728 token、总计16366 token。**不含参数解析调用**，没有推算费用或吞吐量。实际模型标识见api_usage.json。

- cases.json / parsing_cases.json：运行前冻结的问题及标准。
- provenance.json / frozen_metadata.json：代码、索引与标注版本摘要，原索引内容快照。
- answers.json / retrieval.json：完整回答与检索结果；没有API密钥。
- case_metrics.csv：逐题检索得分及依据性核对。
- grounding_review.json：AI评审口径与逐条判定。
- metrics.json：机器可读结果；严格事实幻觉率保留null。
- parsing_results.json：参数解析的成功、失败及原因。

这一轮是小规模开发基线，建议下一轮冻结独立改写、跨文档和缺失知识题，并由人工复核相关性与事实陈述。当前结果不评价海淀区建筑物实物检出召回率：真实地物遗漏率需要独立测绘/普查真值，现有OSM文件不能充当完整真值。
