# GeoAI 产品案例｜让道路周边建筑物筛选可执行、可复核

更新：2026-11-12。阅读顺序：用户任务 → 产品假设 → 方案取舍 → 实现证据 → 尚待验证。

## 1. 谁在什么情况下需要它

聚焦有基础地理数据、需要完成单路段周边建筑物清单的 GIS 初学者或工程助理。典型任务是“对指定路段周围 500 米建筑物做初步筛选，导出给后续学习或资料整理使用”。不把初步相交筛选包装为选址结论、拆迁估算或安全评估。

这是当前收窄后的目标用户假设，并非已通过访谈确认的用户画像。项目建设者具备 GIS/交通场景背景，这能帮助识别问题，但不能替代用户研究。专业设计人员对精度、权威数据和审签的要求更高，暂不作为首批价值验证对象。

## 2. 需求证据与空白

| 判断 | 当前证据 | 允许得出的结论 |
|---|---|---|
| 数据服务不稳定会中断任务 | 项目在线道路请求持续超时，记录于 OnlineData.md | 当前环境应优先本地数据；不能概括所有在线服务不可靠 |
| 自然表达存在规则覆盖缺口 | 同题两条改写规则失败、DeepSeek 成功 | 模型对这两条表达有增益；不能推算总体成功率 |
| 统计口径会影响理解 | 项目使用者曾询问“建筑物总数”的范围 | 本项目结果说明有理解障碍信号；不是用户群体调研结论 |
| 初学者需要更少步骤 | 现有流程需处理坐标、缓冲、相交、导出 | 值得验证的机会；尚无真实用户节时、需求频次或付费意愿数据 |

最小价值假设：在授权数据已就绪时，使用者能独立完成一次筛选，正确解释数量与覆盖范围，并导出可复核结果。首先验证这一点，再评估推广或商业价值。

## 3. 方案为什么这样选

| 决策 | 选择及代价 | 核对方式 |
|---|---|---|
| AI 放在哪里 | 模型提参，GIS 算数；固定工作流而非自主规划 | 解析 JSON 经校验，几何由 GIS 模块计算 |
| 为什么保留表单与规则 | 明确任务用直接选道路/距离即可，无需模型成本；模型作为表达补充 | 当前页面两种输入可用；用户优劣待对照 |
| 如何避免选错道路 | 同名不连通路段拆成候选，由用户看地图确认；增加一次确认 | 海淀区本地库与真实任务验收 |
| 为什么换本地数据 | 超时阻塞后改为持久化索引；牺牲在线新鲜度换取可执行与复现 | 导入版本、道路名索引、快照和重算 |
| RAG 是否必要 | 作为独立知识辅助，不混入建筑物计数；来源可查看 | 已有检索和回答基线，尚缺无 RAG 对照 |

交互自动化、GIS 计算自动化、AI 语言理解的贡献分别评估。对比手工 QGIS 与整套产品只能反映整体工作流差异，不能归因于 AI。

## 4. 当前交付及能证明的结果

- 海淀区及周边数据：2,194 个道路名、33,762 个建筑物，不代表完整行政区覆盖。
- 中关村大街 500 米特定路段：读取 609 个附近建筑物，371 个相交，238 个不相交；保存和历史复现已核验。不是全区建筑数量或现实楼栋普查。
- 相同 10 条开发指令：DeepSeek 链路 10/10，规则 8/10。样本小且非独立用户输入，不宣传 100% 模型准确率。
- 20 题 RAG 开发评测：16 道可回答、4 道无答案；原始输出、失败项和标注口径公开。严格事实幻觉率、真实用户收益未测。

证据：[数据验收](../HaidianData.md)、[最新评测](../ai_quality_20261111/report.md)、[在线回放](https://forpc521-ui.github.io/GeoAI-Assistant/demo-v2/)。

## 5. 项目工作如何对应产品经理能力

| 产品工作 | 项目中可审阅的产物 | 尚缺的证据 |
|---|---|---|
| 定义问题与范围 | 当前 PRD、目标任务、非目标 | 独立目标用户访谈 |
| 方案选型与权衡 | 规则/模型/GIS 分工、本地替代在线的取舍 | 同条件成本和用户对照 |
| 设计人机协作 | 参数校验、路段确认、来源与统计说明 | 用户理解正确率 |
| 验收与迭代 | 原始模型结果、GIS/导出/复现、失败项 | 留出集与独立人工评审 |
| 推动交付 | 本地应用、公开预览、运行回放、版本化材料 | 完整公网服务与运营验证 |

开发方式：项目采用 AI 编码工具辅助实现、排错、测试与文档整理。以上为项目内已有工作与产物，不自动代表建设者独立完成所有代码或所有产品分析；简历中的个人贡献应只选择本人实际参与、能解释并复核的部分。

## 6. 下一步验证与决策

使用[用户验证计划](../../01_Product/ValidationPlan.md)招募接近目标的人完成相同任务，分别观察直接选择与自然语言两种路径。先验证理解与完成，再考虑扩大范围。未完成访谈、用户测试、自然语言收益对照前，项目状态为“可运行原型＋开发验证”，不是已证明需求与商业效果的产品。
