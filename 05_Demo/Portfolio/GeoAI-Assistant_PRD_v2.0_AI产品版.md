# GeoAI Assistant 产品需求文档

**版本：**V2.0｜AI产品版  
**编写日期：**2026年10月27日  
**产品形态：**本地运行的Streamlit Web应用  
**产品阶段：**限定场景MVP，空间分析主线已完成本地验收  
**事实基线：**2026年10月18日评测与浏览器验收。本次核对源码及输入摘要，与该基线一致；未重新运行测试或评测在线模型。

## 1. 产品概述

GeoAI Assistant将GIS知识检索、自然语言参数解析和空间计算结合，帮助用户理解分析方法，并完成可查看、可导出、可复核的空间任务。

产品有两条使用路径：

- **知识问答：**用户提出GIS概念或操作问题，系统检索本地知识资料，由DeepSeek组织回答并展示参考片段。
- **空间分析：**用户指定道路、距离和建筑物对象，系统解析并校验任务，由GIS引擎生成缓冲区、筛选相交建筑物，展示地图、数量、占比和明细，并支持下载及历史复现。

当前空间分析仅支持单道路、单距离的建筑物相交分析。规则或模型负责理解参数，GIS程序负责数量、距离和几何结果；用户通过侧边栏选择功能。

**核心闭环：**提交任务 → 参数校验 → 空间计算 → 解释与展示 → 导出 → 保存与复现。

## 2. 背景、用户与AI使用理由

### 2.1 用户问题与目标

对于不熟悉GIS操作的使用者，道路周边建筑物筛选涉及输入准备、坐标转换、缓冲区生成、空间筛选和结果整理。即使获得数量，还需要知道统计口径、数据范围与复核依据。

| 用户假设 | 典型任务 | 产品目标 |
|---|---|---|
| GIS初学者 | 理解缓冲区概念、查询操作步骤 | 通过有来源的说明理解分析方法 |
| 有初步空间筛选需求的工程或研究人员 | 查看道路周边指定距离涉及哪些建筑物 | 提交明确任务，获得可解释结果和可用文件 |
| 需要复核结果的使用者 | 找回旧任务，确认结果依据 | 查看输入快照与参数，重算并核对差异 |

**用户目标：**知道能做什么，完成当前支持的任务，看懂结果并下载，之后可复核。

**产品/业务目标：**验证文字入口与统一结果页面是否有助于用户完成空间任务，并建立质量及使用效果基线。当前无商业化收益目标，需求频率、用户价值和效率提升尚未经访谈或真实用户对照验证。

用户也可以使用GIS桌面软件或脚本完成任务；本文不假定本产品优于这些路径。

### 2.2 哪些环节值得使用AI

| 环节 | 规则或传统程序能做什么 | AI的预期价值与代价 | 当前取舍 |
|---|---|---|---|
| 标准空间指令 | 固定句式或表单足以提取道路与距离 | AI并非必要，反而增加延迟、成本和不确定性 | 保留无需API的本地规则作为可靠演示路径 |
| 同义表达与自然提问 | 规则扩展需要持续维护表达组合 | 模型可能接受更灵活的措辞，但会漏意图或猜参数 | 可选DeepSeek解析；改进效果必须用独立新用例验证 |
| GIS知识解释 | 资料检索可以返回相关原文 | 模型可组织解释和步骤，但可能产生无依据内容 | RAG问答展示检索片段；回答质量另行评测 |
| 缓冲区、距离和计数 | GIS引擎可按明确参数确定性计算 | 直接让语言模型给数无法提供空间计算依据 | 使用GIS程序计算，模型不生成最终统计数值 |

**AI价值假设：**在保持任务校验和GIS结果可靠的前提下，扩大可接受表达并帮助用户理解知识。当前规则同义改写0/8，是表达覆盖缺口的证据；不能据此推定模型已经解决该问题。若模型提升不足以抵消延迟、成本和错误风险，继续采用规则引导或参数表单。

### 2.3 方案选型与作品集说明

采用“规则/DeepSeek受约束提参＋GIS确定性计算”完成空间任务，知识解释另走“本地检索＋DeepSeek”的RAG路径。当前是预定义任务工作流，没有自主多步规划；不因项目称为Agent就引入多Agent框架。

方案按任务选用：直接API适合参数提取，不直接生成空间数量；RAG提供问答资料依据；现阶段没有微调训练集及收益证据；已有矢量输入不需要多模态或CV重新识别建筑。微调、Agent和多模态的升级条件应由新增需求与同条件实验决定。

完整候选方案对比、成本/延迟/数据安全/算力/幻觉取舍及面试说明见[作品集：方案选型与AI指标](GeoAI_作品集_方案选型与AI指标.md)。该选型是设计判断，未声称对所有技术路线开展过性能实验。

## 4. 主要流程与交互

### 4.1 页面组织

侧边栏包含“GIS智能问答”“道路500米缓冲区分析”“自然语言空间分析”“分析任务记录”四个入口。核心演示从自然语言分析进入，再到历史任务复核。

### 4.2 正常流程

**空间分析：**阅读可用道路和示例 → 输入“分析昌盛路周边500米范围内的建筑物” → 选择规则或模型 → 提交 → 校验参数 → 捕获输入快照并执行计算 → 保存任务 → 查看结果 → 下载 → 历史复现。

**知识问答：**输入问题 → 检索本地知识片段 → 模型组织回答 → 查看回答及参考片段。问答不会自动触发空间计算。

### 4.3 状态与用户反馈

| 状态 | 页面行为与下一步 |
|---|---|
| 初始/历史为空 | 显示示例、支持范围；历史为空时引导先提交分析 |
| 处理中 | 提示正在解析、计算、保存或检索；未完成前不显示新成功结果 |
| 成功 | 展示任务编号、参数、地图、统计和明细，允许筛选与下载 |
| 输入无效/能力不支持 | 说明问题与支持边界，用户改写后重新提交 |
| 数据、API或保存失败 | 给出可操作提示；检查相应条件，或从模型模式改用本地规则 |
| 历史损坏/复现差异 | 提示完整性问题或展示对比报告，保留原任务 |

空间主线新提交先清空旧结果；失败后不能让上一任务的统计和下载被误认为本次成功。详细兜底见第8节。

## 5. 详细产品需求

### 5.1 指令与AI解析

- 去除首尾空白后，指令长度1—500字；包含一条可用道路、一个明确距离及建筑物对象。
- 当前样本道路为昌盛路，距离要求0 < d ≤ 5000米，支持米/公里，并转换“半公里”。本地规则限定约定句式。
- DeepSeek仅提取road_name、distance_m与operation三个字段；操作限定为road_buffer_buildings。
- 程序校验字段、类型、道路白名单、距离范围及与原指令的一致性；已知不支持意图在解析前拦截。任何校验失败均不进入成功任务。
- 当前模型参数解析无概率置信度输出，也没有低置信度自动转人工机制。采用明确校验和用户改写兜底；未知措辞及漏意图风险仍需专项评测。

### 5.2 空间结果与统计口径

- 同名道路要素合并后生成缓冲区，建筑面与其intersects即计入，包括部分相交和边界接触。
- 范围外为本次输入建筑物的补集，按输入要素计数；占比分母为本次全部输入建筑物，不是行政区总建筑数。
- 最短距离为建筑几何到合并道路几何的距离，保留两位小数。
- 计算使用EPSG:32650；输入统一为EPSG:4326，地图及GeoJSON输出为4326。当前投影适用区域受限制。
- 地图、统计和明细来自同一已保存任务；表格可切换相交建筑物与全量建筑物。

### 5.3 下载、归档与复现

| 输出 | 内容与规则 |
|---|---|
| 汇总CSV | 道路、距离、数量和比例；始终统计全部输入 |
| 明细CSV | 标识、名称、最短距离和相交标记等；范围跟随当前筛选 |
| GeoJSON | 缓冲区与相交建筑物，保留空间几何 |
| 历史JSON/ZIP | 清单、输入、结果及引擎归档，用于查看与复核 |

CSV采用UTF-8 BOM，比例存为0—1小数。CSV函数已处理空明细表头与零分母，但不等于主输入支持空图层端到端分析。固定500米旧页保留原GeoJSON导出，CSV与历史闭环以自然语言入口为主。

每次成功提交保存唯一任务、原指令、参数、输入快照、结果、环境和代码摘要；筛选、下载和界面重跑不重复保存。复现跳过模型，使用旧输入/参数及当前引擎，另存关联子任务，不覆盖原记录。比较关键字段、几何与距离，不承诺所有属性或文件字节完全相同。

### 5.4 知识问答与内容要求

现有问答使用中文向量模型与FAISS检索至多3个片段，交给DeepSeek生成回答并展示来源及相似度。提示词要求依据资料、信息不足时说明，且不执行检索资料中的指令；这是提示约束，不是已验证的防幻觉保证。

参考片段不是逐句权威引文。当前没有依据检索分数进行自动拒答的已校准阈值，不能把相似度称为回答正确率。下一轮应检查逐项事实是否受资料支持，并单独评测资料不足的问题。

### 5.5 通用体验与运行要求

输入控件有文字标签，错误可读，地图之外保留统计和表格。完整键盘、屏幕阅读器和跨设备兼容性测试待补。内容必须说明统计口径、当前任务来源及未知项，避免只靠颜色传达结果。

本地规则、GIS计算和历史复现无需模型API；在线模型与部分地图资源依赖网络。现有环境可运行，新机器安装及生产并发未验证，无账号、多租户隔离或用户行为埋点。

## 6. 系统、数据与安全

```text
Streamlit界面
 ├─知识问题 → 中文向量检索/FAISS → DeepSeek回答 → 参考片段
 └─空间指令 → 规则或DeepSeek提参 → 程序校验
                                      ↓
                         输入快照 → GeoPandas/Shapely计算
                                      ↓
                         地图/统计/明细 → CSV与GeoJSON
                                      ↓
                         本地任务归档 → 历史查看/重算对比
```

输入为本地GeoJSON；当前有4个昌盛路道路要素、510个建筑物要素。模型不执行任意代码，也不负责生成空间统计。任务按目录保存manifest、inputs、results和engine；全部写完后发布目录，用SHA-256核查文件完整性，清单本身没有签名。

模型解析通过OpenAI兼容客户端调用deepseek-chat，自然语言页超时30秒、自动重试0次。DEEPSEEK_API_KEY由本机.env加载；模型解析发送指令和道路名，问答发送问题及检索片段。密钥不进入任务包，任务包仍有指令、几何与本地路径。

本地元数据有OpenStreetMap署名和许可链接，但下载渠道、日期、覆盖边界及许可链尚未补齐。公开分发数据前需核实，当前统计不得表述为区域全量；应用按本地个人演示运行。

## 7. AI效果、产品效果与验收线

本节区分**已观测基线**与**下一轮建议验收门槛**。门槛是本项目拟定的迭代目标，不是行业标准，也不表示已达标。

### 7.1 当前基线

2026年10月18日，冻结30条开发者编写指令：12条标准表达、8条同义改写、10条异常；地点和数据均为当前昌盛路样本。

| 层级 | 指标及分母 | 已观测结果 |
|---|---|---|
| 参数解析 | 标准表达参数正确 / 标准12条 | 本地规则12/12 |
| 参数解析 | 同义表达参数正确 / 改写8条 | 本地规则0/8 |
| 任务行为 | 明确拒绝或澄清 / 异常10条 | 10/10 |
| 任务行为 | 有效参数正确或异常处理正确 / 全30条 | 22/30，73.33% |
| 产品闭环 | 解析、计算、保存、重载、ZIP及复现通过 / 全部20条有效指令 | 12/20，60% |
| 条件核验 | 空间/快照复现通过 / 已执行12条 | 各12/12，不是总体成功率 |
| 工程质量 | 既有回归测试 | 39项通过 |
| 模型效果 | DeepSeek解析与RAG回答质量 | 真实在线调用本轮未测 |
| 用户/业务 | 独立完成、采纳、时间节省、收入 | 未测，不填成果数值 |

浏览器验收已确认地图、CSV落盘、ZIP及复现。空间参考实现虽独立逐建筑核对，底层仍共享Shapely/PROJ，不是外部测绘真值。成功业务任务n=12，P50约425ms、P95约786ms，不含冷启动、浏览器渲染和复现，不作为线上SLA。

### 7.2 下一轮评测集与门槛建议

**空间指令集：**保留原30条回归，另建立60条独立新用例：标准有效20、同义有效20、无效输入10、混合不支持要求10。来源采用未参与本轮调试者编写的表达及经知情收集的试用表达；预先人工标注参数或拒绝理由，在调参前冻结，用同一组对比规则与模型。若新用例用于调试，应重新建立留出集。

| 层级 | 建议门槛 | 计算及判定 |
|---|---|---|
| 模型应用链路 | 有效参数全对≥36/40（90%），其中同义表达≥17/20（85%） | 道路、距离、操作同时正确；解析失败与API错误计失败 |
| 边界控制 | 无效输入及混合不支持任务20/20正确处理 | 明确拒绝或澄清；接口故障不算正确拒绝，错误放行阻断该版本试用 |
| 产品闭环 | 全部有效任务闭环≥36/40 | 统计、关键ID、距离、保存、导出、重载及复现全部符合标签和参考 |
| 结果质量 | 已接受任务的参数/图层/统计/导出不得发现不一致 | 若发现不一致，保留样本、修复并补回归，不能仅靠平均分放行 |

**问答评测集：**建议另建30问：资料可回答的概念10、操作步骤10、资料不足/越界10。每问冻结支持片段或“应说明不足”的标签，由人工按事实项检查：支持事实覆盖、无依据断言、来源关联、是否明确说明信息不足。建议可回答20问中至少18问合格，资料不足10问均明确说明不足；出现虚构数据或规范编号则修复后重验。报告须同时给问题通过数和无依据事实项的分子/分母，不能只给综合“准确率”。这些评测尚未执行。

### 7.3 用户、业务指标与采集

| 指标 | 定义与验证方式 | 目标/状态 |
|---|---|---|
| 领先指标：完成过程 | 按模式记录提交、解析、拒绝/失败/成功、导出与复现 | 建议本地最小记录；现有清单不等于完整行为埋点 |
| 产品指标：独立完成率 | 无代操作且正确完成指定分析及导出 / 全部试用任务 | 首轮小样本探索，不先宣称总体比例 |
| 产品指标：结果可采纳 | 受试者检查后确认适合预先指定用途 / 全部产出结果的任务 | 需同时保留不采纳原因；下载不等于采纳 |
| 用户理解 | 正确说明相交口径、分母和数据范围 / 全部受试者 | 任一误用都进入体验改进清单 |
| 业务指标：任务时间与错误 | 与同人、同输入、同目标的手动GIS路径配对比较 | 首轮报告每人结果与中位数；目标为用时下降且不增加错误，尚无提升数字 |

真实试用先确认目标用户、任务和用途；采用平衡操作顺序，说明熟悉度影响。仅收集完成状态、模式、错误类别和必要耗时，事先说明用途，不默认上传原始指令或精确位置。当前不设虚构的用户量、付费或营收目标。

### 7.4 关键AI指标的测量边界

知识问答应分别报告片段检索Recall@K、Precision@K和回答无依据事实率；产品层补充端到端响应时延、满足质量与延迟要求的成功吞吐量、任务后CSAT。当前只有本地成功业务时延有实测，其余上述检索、回答、负载和用户指标均未测，不能用空间参考一致性或工程测试通过率替代。

各指标公式、标注方式、零分母处理、当前结果与后续对照实验，集中记录在[作品集指标说明](GeoAI_作品集_方案选型与AI指标.md)。尚未有真实在线模型账单，成本亦不填虚构数字。

## 8. 失败兜底、能力边界与风险

### 8.1 可执行的兜底规则

| 触发条件 | 当前处理/拟补充要求 | 用户下一步 |
|---|---|---|
| 空/超长、多距离、未知道路、距离越界、缺对象 | 校验不通过，不生成成功任务；显示对应指引 | 按示例补充或改写 |
| 已知高度、人口、路径、预测等不支持要求 | 提示当前能力；不能丢弃附加意图后只执行普通缓冲区 | 删除不支持要求；必要时人工使用其他工具 |
| 模型JSON无效或参数与原文不一致 | 不执行，提示未确认有效任务 | 改成明确句式或选择本地规则 |
| 缺密钥、接口失败/超时 | 不自动重复调用，不生成成功结果 | 检查配置或手动切换规则后再提交 |
| 输入变化、文件读取/计算/保存失败 | 不发布半成品，主线清空旧结果，内部详情留日志 | 检查数据、权限与磁盘后重试 |
| 历史损坏或复现不一致 | 显示问题/差异，保留原任务和可用证据 | 由使用者核对数据、代码与环境，不将差异标为成功 |
| 问答资料不足 | 现有提示词要求说明不足；尚无硬拒答阈值 | 查阅原资料；后续依据人工评测完善提示与拒答策略 |

没有受验证的模型概率评分，也没有自动人工工单。“人工复核”指使用者自行核对参数、资料或GIS工具，不能写成已建成的自动升级流程。FAISS相似度不能直接用作置信度阈值。

### 8.2 明确不承诺的事项

不承诺任意表述都能识别、任意空间任务都可执行、知识回答无幻觉、输入覆盖全区域、结果可用于工程决策，或历史复现能还原模型回答。也不承诺全国自动选投影、生产并发与服务SLA。

关键剩余风险：用户需求未验证；数据范围和来源证据不足；同义表达覆盖低；在线模型/RAG未测；部分旧页仍直接显示异常文本；新机器安装与完整无障碍验收待补。以上均保留为未完成验证，不用文档描述替代实现。

## 10. 迭代顺序与实现交接

| 顺序 | 目标与工作 | 进入下一步的条件 |
|---|---|---|
| M0 已完成 | 原有限定能力、39项回归、30条指令基线与浏览器闭环 | 原失败、输入与环境证据保留 |
| M1 补证与修正 | 核对数据范围/来源/许可，统一旧页异常提示，确认优先用户与任务 | 不作全量统计承诺；对外资料不暴露内部信息 |
| M2 AI效果验证 | 冻结独立指令与问答集，对比规则/模型并记录延迟、请求数和返回usage | 达到选定能力门槛，否则维持规则引导或标为实验能力 |
| M3 产品价值验证 | 真实用户任务、结果理解、采纳与手动对照 | 形成继续/收窄/修改功能的证据，而非预设成功结论 |
| M4 交付更新 | 更新演示、说明、指标和作品集 | 只引用实际完成和验证的能力 |

先按上述顺序验证，再估计周期，不虚构上线日期。需决策的问题为：哪类用户最优先、是否确需自由表达、结果用于什么任务、相交是否符合需求、模型可接受延迟与成本、数据是否允许公开。

后续编码重点检查gis_natural.py、gis_natural_ui.py、gis_result_view.py、gis_history.py、gis_history_ui.py及app.py的问答模块；对照现有test_gis*.py和evaluate_project.py。新增模型评测和错误提示应最小化修改，不重构已通过的GIS计算。此PRD提出新验收目标，不代表本次已实施这些功能或重新测试。
