## 90秒项目介绍

我做的是一个道路周边建筑物分析MVP，面向不熟悉GIS操作但需要做初步空间筛选的人。这个用户需求目前是产品假设，还没有真实用户访谈。

我先把范围收窄到一条道路、一个距离和建筑物对象，避免承诺通用GIS Agent。系统用规则或可选DeepSeek提取参数，再由GIS引擎计算缓冲区、相交建筑和最短距离。结果同时展示地图、表格、统计口径，并支持CSV、GeoJSON与完整任务包。

我特别补齐了错误提示和复现：不支持的高度或预测要求会明确拒绝；每次成功任务保留输入快照和参数，历史重算不再调用模型。2026年10月18日，在昌盛路和510个建筑物的本地样本上，39项工程回归通过。30条开发指令中标准句式12条成功、异常10条正确处理，但8条同义改写失败，因此有效任务闭环是12/20。下一步我会先补齐数据覆盖证据，再用独立新指令和真实用户任务检验理解能力及使用价值。

## 追问与回答依据

| 面试追问 | 诚实且具体的回答 |
|---|---|
| 这算AI产品吗？ | 有可选模型参数提取与RAG问答，但本轮验证的是无需API的空间主线。产品价值在受约束任务和可核验结果，不宣称通用智能Agent。 |
| 为什么先做规则？ | 为当前范围提供稳定可演示的路径，并建立计算与交互基线。代价是同义表达覆盖低，本轮0/8是实测问题；模型提升必须重新评测。 |
| 为什么不让模型直接回答建筑数量？ | 模型只提取参数，数量、距离与几何由GIS产生；可用数据和操作白名单限制任务，错误要求不被静默忽略。 |
| 为什么选择这个范围？ | 单路单距能形成完整的输入、计算、输出与复现契约；当前数据和投影只支撑此范围。更广需求尚未验证。 |
| 500米内是什么意思？ | 建筑面与合并道路缓冲区intersects，包括部分相交和边界接触；并非中心点落入或完全包含。 |
| 105栋是否代表昌盛路周边所有建筑？ | 只代表当前510个输入要素中的105个，下载范围完整性未确认，也没有把要素自动去重成现实栋数。 |
| 为什么投影转换？ | 经纬度不是米制距离；当前区域使用UTM50N计算，再转4326展示。没有自动适配全国投影。 |
| 如何防止模型参数错？ | JSON字段、操作、道路白名单、数值范围、显式距离与原文道路一致性检查，并在解析前拦截已知不支持意图；不保证覆盖所有未知表述。 |
| 怎么证明结果对？ | 工程回归核查UI/表格/CSV/GeoJSON；评测另用逐建筑距离参考核对ID，不能只比较数量。参考仍共享底层库，不能替代测绘或独立GIS真值。 |
| 复现是不是完全相同？ | 使用保存输入与参数、当前代码重算，比较几何及关键字段，距离容差0.011米；不是重新调用模型或保证每个属性、每个字节不变。 |
| 最大问题是什么？ | 规则泛化低、数据覆盖证据不足、没有用户验证；未把这些包装成生产成功。优先补证与独立测试，而非继续堆功能。 |
| 用户量、节省时间和商业收益？ | 没有实测，不填数字。下一轮让目标用户完成同任务，记录完成率、理解错误及手动基线耗时。 |
| 做过线上部署吗？ | 当前本地Streamlit演示，没有生产登录权限、并发或SLA验证，也未公开发布。 |
| 数据安全怎么做？ | .env不入归档，任务ZIP按文件白名单导出；本轮实际密钥字节扫描未命中交付物。但ZIP有几何、指令、本机路径，分享前需要审阅。 |
| 你本人做了什么？ | 按本人实际经历回答需求定义、范围取舍、验收设计、错误发现、文档与实现协作；不要把AI辅助工作伪装成独立经历。 |

## 产品取舍与后续计划

保留已通过的GIS计算和自然语言解析，以可追溯、可解释、可导出作为本期完成条件。当前不为提高评测分数扩写规则，不增加任意上传或多步Agent。下一阶段按证据推进：补齐数据来源和覆盖边界 → 收集新的同义表达/不支持混合意图盲测集 → 比较规则引导和模型解析 → 真实用户任务与手动操作对照。只有完成测量后才在简历补充收益。
