版本：V1\.2（项目介绍精简版）

## 一、产品概述

GeoAI Assistant 是一个把大语言模型、GIS 知识检索和空间计算结合起来的分析助手。它提供两类能力：一类是帮用户理解 GIS 概念和操作方法，另一类是把明确的空间分析指令转换成地图、统计、明细以及可导出的结果。

当前的核心场景是道路周边建筑物分析。用户输入道路名称和缓冲距离后，系统先做参数解析和校验，再由 GIS 引擎计算相交建筑物及其距离，整个过程支持结果下载、任务保存和历史复现。整个交付流程是：提出任务、解析校验、空间计算、查看与解释结果、导出、历史复核。

需要说明的是，AI 只负责知识回答和可选的任务参数提取，建筑物数量、距离和空间范围这些结果都由 GIS 程序计算。功能入口放在侧边栏，用户按需选择。

## 二、背景、用户与AI使用理由

### 2\.1 项目背景与需求

传统 GIS 软件具备较为完善的空间数据处理和分析能力，但在实际使用过程中，用户通常需要掌握一定的 GIS 专业知识，熟悉数据格式、坐标系、空间分析工具及其操作流程。

例如，用户希望统计某条道路周边 500 米范围内的建筑物数量，传统方式需要自行准备道路和建筑物数据，完成数据加载、坐标系检查、缓冲区建立、空间相交分析及统计计算，最后还需要人工整理结果。

对于 GIS 初学者和非专业用户而言，上述操作具有一定的学习成本。

GeoAI Assistant 引入大语言模型与 RAG 技术，将自然语言理解、GIS 知识检索和传统空间分析能力相结合，使用户能够通过自然语言描述分析需求，由系统识别任务参数并调用对应的 GIS 分析流程。

产品的核心设计思路不是利用大模型替代 GIS 算法，而是让 AI 负责理解用户需求、组织专业知识和辅助结果解释，让确定性 GIS 算法负责实际空间计算。

### 2\.2 用户问题与目标

1\.对于不熟悉GIS操作的使用者，本产品整理GIS软件的使用手册以及相关规范作为知识库，用户想查缓冲区这类概念、理解道路周边建筑物的筛选逻辑，以及看重输入示例、操作引导和结果解释。

2\.市政道路规划人员，铁路选线设计人员等有空间筛选需求的人员，通过将已有地理数据导入系统，可以分析道路周围的建筑物情况，对于建筑规划选址，铁路选线提供可靠帮助。

|用户假设|典型任务|产品目标|
|---|---|---|
|GIS初学者|理解缓冲区概念、查询操作步骤|通过有来源的说明理解分析方法|
|有初步空间筛选需求的工程或研究人员（如市政道路规划人员，铁路设计人员等）|查看道路周边指定距离涉及哪些建筑物|提交明确任务，获得可解释结果和可用文件|

用户目标：知道能做什么，完成当前支持的任务，看懂结果并下载，之后可复核。

产品/业务目标：验证文字入口与统一结果页面是否有助于用户完成空间任务，并建立质量及使用效果基线。

### 2\.3 与传统方式相比，哪些环节值得使用AI

#### 没有 AI 时的传统工作流程

以道路周边建筑物缓冲区统计为例，传统 GIS 工作流程如下：

1. 用户明确分析需求及目标道路。

2. 自行寻找并下载道路和建筑物空间数据。

3. 使用 QGIS 加载数据，检查数据格式和坐标系。

4. 筛选目标道路，清理无关道路要素。

5. 将数据转换为适合距离计算的投影坐标系。

6. 使用缓冲区工具建立指定距离的道路缓冲区。

7. 使用空间相交或空间连接工具筛选建筑物。

8. 使用属性表或统计工具计算建筑物数量及占比。

9. 人工整理地图、统计表和分析说明。

该方式能够完成专业空间分析，但用户需要具备一定的 GIS 软件操作能力，并且需要在多个工具和处理步骤之间切换。

#### 引入 AI 后的工作流程

GeoAI Assistant 将上述操作整合为更加简洁的交互流程：

1. 用户通过自然语言描述分析需求。

2. AI 自动识别道路名称、距离和分析类型。

3. 系统完成参数校验并调用 GIS 分析工具。

4. GIS 引擎自动完成缓冲区和建筑物空间相交计算。

5. 页面展示地图、统计指标及分析结果。

6. 用户查看或导出分析成果。

用户不再需要记忆具体 GIS 工具名称和完整操作路径，而是可以通过自然语言表达需求。

|对比维度|传统 GIS 工作方式|GeoAI Assistant|
|---|---|---|
|交互方式|菜单、工具和参数设置|自然语言交互|
|专业知识获取|搜索文档、查阅教程|RAG 检索与 AI 问答|
|任务理解|用户自行拆解分析步骤|AI 提取任务意图与参数|
|空间分析|手动配置 GIS 工具|自动调用 GIS 分析流程|
|统计结果|人工统计和整理|自动计算并展示|
|错误处理|用户自行排查|系统进行参数校验并提示|
|结果解释|用户自行撰写|AI 辅助组织分析说明|

### 2\.4 AI 带来的核心价值

1. **降低 GIS 使用门槛。**

将专业工具操作转换为自然语言交互，使不熟悉 GIS 软件操作的用户也能够表达分析需求。

2. **减少重复性操作。**

将任务解析、参数校验、空间计算和统计结果展示串联起来，减少用户在多个工具之间切换的操作负担。

3. **提高专业知识获取效率。**

通过 RAG 技术建立 GIS 专业知识检索能力，帮助用户快速定位相关知识和操作方法。

4. **增强 GIS 分析的交互性。**

用户可以通过调整距离、修改分析对象等方式继续提出需求，而不必每次从头学习工具操作流程。

5. **形成可扩展的 GIS 智能分析框架。**

通过将自然语言理解与 GIS 工具解耦，后续可以逐步接入道路、建筑物、土地利用等更多空间数据及分析工具。

## 三、产品目标与范围

产品的目标是交付一个可操作、可解释、可导出、可复核的空间分析流程，并建立质量基线，为后续的用户试用和理解能力优化提供依据。落到用户侧，是能提交当前支持的任务、看懂结果及数据范围、获得可用文件，并在需要时找回分析依据。

本期范围包括：

- GIS 知识问答：检索本地知识库，通过 DeepSeek 生成回答并展示参考片段。

- 自然语言空间分析：支持当前数据中的单条道路、单个距离与建筑物对象，计算缓冲区、相交结果、内外数量和占比。

- 结果展示与导出：地图、统计、距离明细、CSV 和 GeoJSON。

- 历史任务管理：保存输入与结果，查看记录，下载任务包，使用快照复现。

- 保留固定 500 米分析页面，提供既有道路结果核验和模拟数据演示。

暂不支持的功能包括：多道路比较、任意 GIS 任务规划、完全包含筛选、人口或建筑高度统计、路径规划、时序预测、CAD/BIM 及遥感分析。当前也不包含账号体系、多租户权限和生产服务部署。

## 四、核心功能

### 4\.1 GIS 智能问答

用户输入 GIS 概念、空间分析方法或操作流程问题后，系统从本地知识资料中检索相关片段，交给 DeepSeek 组织回答，并展示来源片段及相似度，方便用户自己检查回答依据。

这里有几个细节要求：空问题要提示补充；接口出错要有反馈；参考片段只是检索依据，不代表每句话都经过权威核验。这个模块已经实现，但本轮没有评测在线回答质量。

### 4\.2 自然语言空间分析

以"分析昌盛路周边 500 米范围内的建筑物"为例，系统需要做到：

- 输入引导：展示可用道路、示例句式及参数说明。

- 参数范围：指令 1—500 字；单道路、单距离；距离大于 0 且不超过 5000 米，支持米/公里及"半公里"转换。

- 解析方式：本地规则无需 API，支持约定句式；DeepSeek 作为可选的参数解析方式。

- 参数校验：检查道路、操作类型、数值范围及与原指令的一致性，通过后执行。

- 能力提示：对已知不支持的要求明确提示，不静默忽略附加需求。

- 失败处理：新提交清空旧结果；解析、计算或保存失败时不展示本次成功结果。

这里有个边界需要说清楚：本地规则的同义表达覆盖有限；模型解析也必须经过相同的参数边界校验，不能直接决定空间分析结果。

### 4\.3 结果展示与解释

结果页面展示道路、缓冲区、全部建筑物及相交建筑物图层，同时显示建筑物总数、范围内外数量与占比。表格包含可用标识、名称、最短道路距离和相交标记，支持在"相交明细"和"全部建筑物"之间切换。

统计口径统一说明如下：同名道路要素合并后生成缓冲区；建筑面只要与缓冲区相交就计入，包含部分相交和边界接触。按本次输入要素计数；范围外是输入建筑物中其余要素，占比分母为本次输入建筑物总数。距离为建筑几何到合并道路几何的最短距离，保留两位小数。当前以 EPSG:32650 进行米制计算，地图和 GeoJSON 输出为 EPSG:4326。统计只覆盖本地输入数据，不等于行政区全量，也不自动等同于现实独立楼栋数量。

页面同时展示本次输入快照、坐标系、要素数及内容摘要，说明结果依据。

### 4\.5 结果导出

导出分几种：统计汇总 CSV 包含道路、距离、总数、相交数、范围外数及占比，汇总始终覆盖全部输入建筑物；当前表格 CSV 包含标识、名称、距离及相交标记等明细，范围随"仅查看相交建筑物"切换；GeoJSON 导出缓冲区和相交建筑物几何及属性，用于后续空间处理；任务 JSON/ZIP 包含参数、来源、环境、输入快照、结果与引擎归档，在历史任务页面下载，用于复核。

CSV 采用 UTF\-8 BOM，比例写为 0—1 小数。自然语言与历史结果页面支持上述 CSV 功能；固定 500 米页面保留原有 GeoJSON 导出。

### 4\.7 历史任务与复现

成功分析会自动生成唯一任务编号，保存原指令、参数、输入快照、结果、计算环境和代码摘要。筛选、下载或界面重跑不会重复创建任务。

用户可以查看原结果、下载任务包，或使用当时输入和参数重新计算。复现跳过模型，采用当前计算程序，生成关联原任务的新记录，并比较图层、关键标识、相交标记和距离。原任务保持不变，环境变化或结果差异会在页面提示。

### 4\.8 体验与运行要求

界面保留清晰标签和文字反馈，结果除地图外还可通过统计与表格查看。完整键盘、屏幕阅读器及跨设备兼容性仍待验证。

应用在现有本地环境运行；规则计算和历史复现无需模型 API，在线问答及模型解析依赖密钥和网络。现阶段通过任务清单与评测日志记录运行依据，尚无用户行为埋点。

## 五、主要流程与验收标准

### 5\.1 用户流程

空间分析的完整流程是：先选择功能，阅读范围与示例，输入指令和解析方式，提交校验，计算并保存，然后查看地图、统计和明细，导出，最后进入历史复现。知识问答流程更简单：输入问题，检索知识片段，AI 生成回答，查看回答及参考来源。

### 5\.2 AI在产品中的工作流程

对于 GIS 知识问答，工作流程：

用户提出 GIS 问题

→ 文本向量化

→ FAISS 知识检索

→ 获取相关知识片段

→ DeepSeek 结合检索内容生成回答。

对于空间计算，工作流程采用另一条链路：

用户自然语言输入

→ DeepSeek 语义理解

→ 任务参数提取与合法性校验

→ GIS 分析工具调用

→ GeoPandas / Shapely 空间计算

→ 真实统计结果返回

→ AI 辅助解释与结果展示。

### 5\.3 验收标准

页面在不同状态下要有对应的处理：

- 初始或暂无记录：给出示例、输入框或创建任务引导。

- 处理中：明确显示正在解析、计算或检索。

- 成功：展示结果及任务编号，可查看、筛选和下载。

- 输入错误或能力不支持：说明问题与支持范围，用户修改后重试。

- API 或执行失败：提示检查配置、网络、数据或保存条件，可切换本地规则。

- 历史损坏或复现差异：提示核验问题或展示对比报告，保留原任务。

### 6\.2 系统架构

系统划分为五个主要层次。

**第一层：用户交互层**

使用 Streamlit 提供 GIS 智能问答、自然语言空间分析、道路缓冲区分析和任务记录等页面。

**第二层：AI 能力层**

通过 DeepSeek 实现自然语言理解和任务参数提取；通过 RAG 提供 GIS 专业知识检索能力。

**第三层：业务调度层**

负责任务解析、参数校验、道路匹配、分析任务分发及错误处理。

**第四层：GIS 计算层**

通过 GeoPandas 和 Shapely 执行道路缓冲区建立、建筑物相交判断、空间统计及结果处理。

**第五层：数据存储与结果层**

包括本地道路和建筑物 GeoJSON 数据、GIS 知识库、FAISS 向量索引、分析结果及任务记录。

### 6\.3 关键技术设计

### RAG 检索流程

原始 PDF / 文本资料

→ 文本提取

→ 文本分块

→ Sentence\-Transformers 向量化

→ FAISS 建立索引

→ 用户问题检索

→ DeepSeek 结合检索内容生成回答。

### GIS 空间分析流程

读取道路和建筑物 GeoJSON

→ 检查几何有效性

→ 坐标系统一

→ 转换为适用的米制投影坐标系

→ 道路缓冲区建立

→ 建筑物空间相交判断

→ 数量及占比计算

→ 输出统计结果和空间数据。

当前昌盛路实验采用 EPSG:32650 进行米制空间计算，结果可转换EPSG:4326 供地图展示。该投影设置适用于当前北京昌平实验区域，不能直接作为所有地区的通用投影方案。

```Plaintext
Streamlit交互界面
                               │
              ┌────────────────┴────────────────┐
              │                                 │
         GIS知识问答                       空间分析与复核
              │                                 │
     中文向量模型 + FAISS                本地规则 / DeepSeek
              │                                 │
        检索本地知识片段                    任务参数校验
              │                                 │
      DeepSeek生成回答                  GeoPandas / Shapely计算
              │                                 │
        回答与参考来源                  地图、统计、明细及导出
                                                │
                                        本地任务归档与复现
```

系统结构上，Streamlit 交互界面分两条线。GIS 知识问答这条线负责用中文向量模型和 FAISS 检索本地知识片段，由 DeepSeek 生成回答，再输出回答与参考来源；空间分析与复核这条线负责用本地规则或 DeepSeek 解析任务参数，经过任务参数校验，由 GeoPandas/Shapely 完成计算，输出地图、统计、明细及导出，最后落到本地任务归档与复现。

知识问答使用 BAAI/bge\-small\-zh\-v1\.5 与 FAISS 检索，再调用 DeepSeek。空间分析将指令转为道路、距离和操作三个参数，由现有 GIS 程序执行，不运行模型生成的代码。

输入为本地道路与建筑物 GeoJSON。任务按目录存储清单、输入、结果和引擎源码快照；全部写入完成后才发布任务目录，通过 SHA\-256 检查文件完整性。复现使用当前引擎，不自动执行归档源码；一致性比较不等于文件逐字节完全相同。

API 密钥存放于本机 \.env，不进入任务包。任务包仍含指令、几何和本地来源路径，分享前应审阅。当前无账号访问控制，应按本地个人应用使用。

## 七、AI效果、产品效果与验收线

本节区分**已观测基线**与**下一轮建议验收门槛**。门槛是本项目拟定的迭代目标，不是行业标准，也不表示已达标。

### 7\.1 当前基线

2026年10月18日，冻结30条开发者编写指令：12条标准表达、8条同义改写、10条异常；地点和数据均为当前昌盛路样本。

|层级|指标及分母|已观测结果|
|---|---|---|
|参数解析|标准表达参数正确 / 标准12条|本地规则12/12|

## 八、失败兜底、能力边界与风险

### 8\.1 可执行的兜底规则

|触发条件|当前处理/拟补充要求|用户下一步|
|---|---|---|
|空/超长、多距离、未知道路、距离越界、缺对象|校验不通过，不生成成功任务；显示对应指引|按示例补充或改写|
|已知高度、人口、路径、预测等不支持要求|提示当前能力；不能丢弃附加意图后只执行普通缓冲区|删除不支持要求；必要时人工使用其他工具|
|模型JSON无效或参数与原文不一致|不执行，提示未确认有效任务|改成明确句式或选择本地规则|
|缺密钥、接口失败/超时|不自动重复调用，不生成成功结果|检查配置或手动切换规则后再提交|
|输入变化、文件读取/计算/保存失败|不发布半成品，主线清空旧结果，内部详情留日志|检查数据、权限与磁盘后重试|
|历史损坏或复现不一致|显示问题/差异，保留原任务和可用证据|由使用者核对数据、代码与环境，不将差异标为成功|
|问答资料不足|现有提示词要求说明不足；尚无硬拒答阈值|查阅原资料；后续依据人工评测完善提示与拒答策略|

没有受验证的模型概率评分，也没有自动人工工单。“人工复核”指使用者自行核对参数、资料或GIS工具，不能写成已建成的自动升级流程。FAISS相似度不能直接用作置信度阈值。

### 8\.2 明确不承诺的事项

不承诺任意表述都能识别、任意空间任务都可执行、知识回答无幻觉、输入覆盖全区域、结果可用于工程决策，或历史复现能还原模型回答。也不承诺全国自动选投影、生产并发与服务SLA。

关键剩余风险：用户需求未验证；数据范围和来源证据不足；同义表达覆盖低；在线模型/RAG未测；部分旧页仍直接显示异常文本；新机器安装与完整无障碍验收待补。以上均保留为未完成验证，不用文档描述替代实现。

## 十、 产品能力边界与后续规划

### 10\.1 当前产品能力

当前版本以昌盛路及其周边建筑物数据作为实验场景，重点验证 GIS 知识问答、自然语言任务解析和道路缓冲区建筑物统计能力。

已完成并经过相应测试的功能包括：

1\.GIS 知识库检索与问答。

2\.基于自然语言的道路缓冲区分析任务解析。

3\.中文距离表达及单位转换。

4\.道路缓冲区建立。

5\.建筑物空间相交判断。

6\.建筑物数量和占比统计。

7\.参数异常及部分不支持任务的拦截。

### 10\.2 数据接入规划

为了避免产品仅依赖昌盛路这一固定实验数据集，后续规划三种数据接入方式：

方式一：内置示例数据

保留昌盛路及建筑物数据，供用户直接体验和产品演示。

方式二：用户上传空间数据

支持用户上传道路和建筑物 GeoJSON、GeoPackage 或其他经过适配的矢量数据，完成格式、坐标系、几何类型及数据完整性检查。

方式三：在线获取空间数据

后续考虑接入 OpenStreetMap 等公开数据源，允许用户根据地区和道路名称获取道路及建筑物数据。

其中，用户上传和在线自动获取功能在未完成开发和验证之前，属于产品规划，不应描述为当前已经实现的功能。

### 10\.3 后续迭代方向

1\.扩展用户上传空间数据能力。

2\.增加道路名称自动识别和道路匹配能力。

3\.接入在线 GIS 数据获取服务。

4\.扩展建筑物、土地利用等更多空间分析任务。

5\.完善分析报告自动生成及结果追溯。

6\.根据实际用户测试持续优化自然语言解析的准确性和任务执行稳定性。
