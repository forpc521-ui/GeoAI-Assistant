# GeoAI 项目评测

运行环境为项目现有 venv。默认只测本地规则，不产生 API 请求：

```powershell
cd D:\GeoAI-Assistant
.\venv\Scripts\python.exe .\04_Code\evaluate_project.py --mode local
```

同时评测真实 DeepSeek（使用现有 `.env` 配置，最多 30 条用例，部分异常由前置校验直接处理，不会请求接口）：

```powershell
.\venv\Scripts\python.exe .\04_Code\evaluate_project.py --mode both
```

默认报告保存到 `05_Demo/evaluation_reports/<时间与唯一编号>/`。也可用 `--output-dir` 指定一个尚不存在的目录，防止覆盖以前的评测结果。

## 产物

- `report.html`：离线浏览器报告。
- `report.md`：可读的 Markdown 报告。
- `case_results.csv`：逐条用例结果和阶段耗时。
- `results.json`：完整指标、参数、原始模型响应、API usage、失败原因和闭环核验。
- `cases.json`：本轮实际使用的冻结用例。
- `reference.json`：独立逐建筑最短距离参考计算与筛选 ID。
- `provenance.json`：输入/代码 SHA-256、依赖版本和评测配置。
- `regression.log`：Streamlit AppTest 与工程回归完整日志。
- `evidence/inputs` 和 `evidence/code`：评测时的数据及代码快照。
- `evidence/tasks` 和 `evidence/downloads`：隔离的分析/复现任务、导出 ZIP，均不混入正式任务记录。

## 评分规则

用例 v1 有 30 条：12 条标准表达、8 条同义改写、10 条异常。20 条有效指令都必须进入有效任务成功率的分母，解析失败不能剔除。异常指令只有被明确拒绝或要求澄清才算正确，API 连接失败或限流不能算正确拒绝。未配置或未选择 DeepSeek 时显示未执行，不输出虚假的准确率。

本地规则和 DeepSeek 使用同一份用例；DeepSeek指标评估的是“模型＋产品前置与后置校验”的整体链路，不是脱离应用的基础模型能力。

业务任务成功要求参数正确、真实 GIS 结果通过独立逐建筑距离参考核验、任务持久化和重载正确、ZIP中结果文件通过校验。闭环成功还要求快照复现结果与原结果及独立参考相符。复现不会重新请求模型。

耗时使用本机计时器实测，每条用例每种模式执行一轮，不代表线上 SLA。业务耗时包含解析、计算保存、重载及ZIP导出，不包含浏览器渲染、评测参考计算或复现。评测前已读取数据与加载依赖，故不计冷启动。并行 API 解析固定最多3个请求；记录请求数、实际返回模型标识和usage，不引用价格或推算未知费用。

## 真实性和使用边界

这是开发者编写的小规模开发评测集，未经过独立用户评审；参考实现底层仍使用 Shapely 和 PROJ，不是 QGIS 或测绘真值。用例不能代表自然语言的全部表达，数据只涵盖当前导出的道路及建筑物。尚未验证下载区域是否完整覆盖指定缓冲区。

测试失败必须保留，不应通过更改标签、删除样本提高成绩。后续修改产品时请保留基线目录，用相同用例回归，并额外增加独立的新样本以降低对已有用例过拟合的风险。

简历仅能引用报告中带明确分母、时间、数据范围的实测指标，不能据此宣称真实用户数、节省人工时间、线上稳定性或任何尚未测量的收益。API密钥和 `.env` 不进入报告、代码快照或任务包。
